## 1. Назначение и цели

Единый веб-сайт для ведения претензионно-исковой работы страховой компании. Сайт заменяет разрозненные таблицы и переписку между подразделениями.

**Цели:**
1. Вести единый реестр входящих и исходящих исков (претензий) с предметом, суммой, ответственным работником, стадией и исходом.
2. Планировать участие в судебных заседаниях через общий календарь.
3. Автоматически уведомлять:
   - подразделение по выплатам о поступлении исков о взыскании страховой выплаты, чтобы сформировать резерв заявленных, но неурегулированных убытков (РЗУ);
   - бухгалтерию о вступлении в силу судебного акта по входящему иску, чтобы произвести оплату.
4. Хранить процессуальные и платёжные документы в карточке дела.
5. Получать аналитический отчёт о претензионно-исковой работе за период.

## 2. Пользователи и роли

| Подразделение | Что делает на сайте |
|---|---|
| Юридическое подразделение | Вносит и ведёт дела, заседания, исход, прикрепляет иски и судебные акты, видит все уведомления, формирует отчёт |
| Подразделение по выплатам | Получает уведомления о формировании и корректировке РЗУ, отмечает их исполненными, смотрит реестр и отчёт |
| Бухгалтерия | Получает уведомления об оплате по судебным актам, прикрепляет платёжные поручения, отмечает уведомления исполненными |

**Выбор подразделения.** Пользователь выбирает своё подразделение в шапке сайта. Выбор запоминается в браузере и определяет, какие уведомления показываются по умолчанию и что считает счётчик новых уведомлений.

**Права доступа** (задаются владельцем через меню «Поделиться»):

| Роль | Права |
|---|---|
| Наблюдатель / Комментатор | Только просмотр |
| Участник | Создание и изменение дел, отметка уведомлений, загрузка файлов, удаление своих файлов |
| Редактор / Владелец | Всё перечисленное, плюс удаление любых файлов |

Файлы, загруженные участниками, видны только сотрудникам организации, вошедшим в свою учётную запись.

## 4. Функциональные требования

### 4.1. Реестр дел

**Сводные плитки:**
- входящие иски в работе и сумма требований к компании;
- исходящие иски в работе и сумма требований компании;
- число заседаний в ближайшие 14 дней;
- число неисполненных уведомлений.

**Фильтры:**
- направление (все, входящие, исходящие);
- стадия, включая отдельное значение «Акт вступил в силу»;
- исход, включая «Исхода ещё нет»;
- ответственный работник;
- текстовый поиск по № дела, суду, контрагенту, предмету, № договора, № убытка, ответственному и категории.

**Колонки таблицы:**
- направление;
- № дела, суд и число прикреплённых документов;
- контрагент (истец или ответчик);
- предмет иска и категория;
- сумма требований;
- ответственный;
- статус;
- исход, дата акта или дата вступления в силу;
- ближайшее заседание.

**Сортировка:** по ближайшему заседанию, затем по дате создания (новые выше).

**Экспорт:** кнопка «Скопировать таблицу для Excel» копирует отфильтрованные строки в буфер в виде таблицы с разделителями-табуляциями.

**Примеры:** демонстрационные дела помечены «пример». Кнопка «Удалить примеры» удаляет их вместе с уведомлениями.

### 4.2. Карточка дела

Карточка открывается кликом по строке реестра, заседанию в календаре или уведомлению. Разделы карточки:
- основные сведения;
- исход дела;
- судебные заседания;
- документы;
- примечания;
- уведомления по делу.

Кнопки: «Редактировать», «Удалить» (с подтверждением; удаляются и прикреплённые файлы, уведомления остаются в истории), «Закрыть».

### 4.3. Форма дела (создание и редактирование)

| Поле | Тип | Обязательное | Значения / примечания |
|---|---|---|---|
| Направление | список | да | Входящий (иск к компании) / Исходящий (иск компании) |
| Категория | список | нет | Взыскание страховой выплаты, Регресс, Суброгация, Взыскание страховой премии, Договорной спор, Трудовой спор, Иное |
| Дата поступления / подачи иска | дата | нет | По умолчанию сегодня; основа для отчёта |
| № дела | текст | нет | Например, 7527-26-00-2/1234 |
| Суд | текст | нет | |
| Истец / Ответчик | текст | да | Подпись меняется по направлению |
| Сумма требований, ₸ | число | нет | |
| Предмет иска | текст | да | |
| № договора страхования | текст | нет | |
| № убытка | текст | нет | |
| Ответственный работник | текст с подсказками | да | Подсказки берутся из уже внесённых ФИО |
| Стадия | список | да | Претензия, Первая инстанция, Апелляция, Кассация, Приостановлено, Исполнение, Завершено |
| Судебные заседания | список строк | нет | Дата, время, примечание (зал, судья, вид заседания); можно добавлять и удалять |
| Исход | список | нет | Иск удовлетворён; Иск удовлетворён частично; Отказано в иске; Мировое соглашение; Иск оставлен без рассмотрения; Производство прекращено |
| Присуждённая сумма, ₸ | число | нет | |
| Дата вынесения судебного акта | дата | нет | |
| Дата вступления в силу | дата | нет | |
| Примечания | текст | нет | |

**Проверки при сохранении:**
- обязательные поля заполнены;
- дата вступления в силу не раньше даты вынесения акта;
- если указана дата вступления в силу, указан и исход.

**Подсказки в форме:**
- при выборе категории «Взыскание страховой выплаты» для входящего иска форма предупреждает, что подразделение по выплатам получит уведомление;
- при заполнении исхода и даты вступления в силу форма показывает, когда бухгалтерия получит уведомление об оплате.

После создания дела сразу открывается его карточка, чтобы прикрепить документы.

### 4.4. Статус и исход дела

- **Статус** = стадия дела. Если дата вступления в силу наступила, вместо стадии показывается «Акт вступил в силу».
- **Исход** окрашивается с точки зрения компании:

| Направление | В пользу компании (зелёный) | Не в пользу (красный) | Нейтрально |
|---|---|---|---|
| Входящий | Отказано в иске | Иск удовлетворён, удовлетворён частично | Мировое соглашение, остальные |
| Исходящий | Иск удовлетворён, удовлетворён частично | Отказано в иске | Мировое соглашение, остальные |

- **Дело «в работе»**: стадия не «Завершено» и акт ещё не вступил в силу.

### 4.5. Календарь судебных заседаний

- Сетка месяца, неделя с понедельника; переключение «←», «Сегодня», «→».
- В ячейке дня: до 3 заседаний (время и № дела, цвет по направлению), остальные свёрнуты в «ещё N».
- Клик по заседанию открывает карточку дела.
- Под сеткой список «Ближайшие заседания (30 дней)»: дата, время, № дела, контрагент, суд, примечание, предмет, направление, ответственный.

### 4.6. Документы по делу

**Виды документов:**
1. Исковое заявление
2. Судебный акт
3. Платёжное поручение: госпошлина за подачу иска
4. Платёжное поручение: выплата по решению суда
5. Претензия / ответ на претензию
6. Иной документ

**Реквизиты файла:**
- вид документа;
- номер;
- дата;
- сумма (только для платёжных поручений);
- имя файла;
- кто и когда загрузил.

**Ограничения:**
- форматы: PDF, JPG, PNG; Word нужно предварительно сохранить в PDF;
- размер файла до 20 МБ.

**Автозаполнение:**
- для платёжного поручения о выплате сумма берётся из присуждённой суммы;
- для судебного акта дата берётся из даты вынесения акта;
- в бухгалтерии вид документа по умолчанию — платёжное поручение о выплате.

**Комплектность.** В карточке показано, каких документов не хватает:

| Документ | Когда ожидается |
|---|---|
| Исковое заявление | стадия не «Претензия» |
| ПП: госпошлина | исходящий иск |
| Судебный акт | указан исход или дата акта |
| ПП: выплата по решению | входящий иск, акт вступил в силу, исход «удовлетворён», «удовлетворён частично» или «мировое соглашение» |

**Удаление:** в два клика («Удалить» → «Точно удалить?»).

**Связь с уведомлениями.** Загрузка платёжного поручения о выплате по решению суда автоматически отмечает исполненными открытые уведомления бухгалтерии об оплате по этому делу. Номер и дата поручения записываются в уведомление.

### 4.7. Автоматические уведомления

**Правила формирования:**

| № | Условие | Получатель | Действие |
|---|---|---|---|
| У1 | Входящий иск категории «Взыскание страховой выплаты» | Подразделение по выплатам | Сформировать РЗУ на сумму требований |
| У2 | Входящий иск; дата вступления в силу наступила; исход «удовлетворён», «удовлетворён частично» или «мировое соглашение» | Бухгалтерия | Произвести оплату на присуждённую сумму (если не указана, на сумму требований) |
| У3 | Входящий иск о страховой выплате; акт вступил в силу; исход указан | Подразделение по выплатам | Скорректировать РЗУ по присуждённой сумме, а при отказе или прекращении расформировать резерв |

**Механика:**
- Уведомления создаёт сайт при открытии любым пользователем с правом записи. Дополнительно сайт перепроверяет правила раз в час, пока страница открыта.
- Если дата вступления в силу в будущем, уведомление появится при первом открытии сайта в эту дату или позже.
- У каждого уведомления постоянный идентификатор по схеме «дело + тип», поэтому дублей не бывает.
- Изменение дела после создания уведомления не меняет и не отменяет уже созданное уведомление.

**Содержимое уведомления:**
- подразделение, дата и время;
- заголовок;
- № дела, контрагент, № договора и № убытка;
- требуемое действие;
- сумма;
- ответственный юрист.

**Работа с уведомлениями:**
- кнопки «Отметить исполненным» (сохраняются дата и сотрудник) и «Открыть дело»;
- фильтры по получателю (моё подразделение, выплаты, бухгалтерия, все) и состоянию (новые, исполненные, все);
- над списком показаны правила У1–У3.

**Каналы доставки:** только на сайте. Отправка по почте или в мессенджер в MVP не реализована.

### 4.8. Аналитический отчёт

**Период:** год (из имеющихся данных) и квартал или «весь период». Заголовок отчёта содержит период.

**Правила отнесения к периоду:**
- поступление: по дате поступления или подачи иска (если она не заполнена, по дате внесения в реестр);
- рассмотрение: по дате вынесения судебного акта (учитываются дела с исходом);
- оплата и госпошлина: по дате платёжного поручения (если она не заполнена, по дате загрузки);
- показатели «в работе» берутся на текущую дату.

**Состав отчёта:**

1. **Сводные плитки:**
   - поступило входящих и подано исходящих исков, с суммами;
   - рассмотрено дел и доля решённых в пользу компании;
   - присуждено с компании и в пользу компании, каждое из заявленного;
   - заседания за период и число дел в работе.
2. **«Итоги»** — автоматически собранный текст с ключевыми цифрами для служебной записки.
3. **График поступления дел по месяцам:** входящие и исходящие столбцами, подсказка при наведении. Для «всего периода» берутся не более 24 последних месяцев.
4. **Исходы рассмотренных дел** по направлениям с итогом: в пользу, частично, не в пользу, мировое, доля в пользу.
   - «В пользу компании» для входящих: отказ в иске, оставление без рассмотрения, прекращение.
   - «В пользу компании» для исходящих: удовлетворение иска.
5. **Денежные показатели:**
   - входящие: заявлено, присуждено с компании, отклонено или снижено (сумма и %);
   - исходящие: заявлено, присуждено в пользу компании;
   - акты по входящим искам, вступившие в силу, и сумма к оплате;
   - оплачено по судебным актам (сумма платёжных поручений);
   - уплачено госпошлины (сумма платёжных поручений).
6. **По категориям споров:** входящие, исходящие, сумма требований, рассмотрено, в пользу компании.
7. **Страховые выплаты и уведомления:**
   - поступившие иски о страховой выплате и их сумма;
   - нерассмотренные иски о страховой выплате сейчас и их требования (база для РЗУ);
   - уведомления выплатам и бухгалтерии: создано, исполнено, среднее время исполнения в днях.
8. **По ответственным работникам:** в работе сейчас, поступило или подано, заседаний, рассмотрено, в пользу компании, доля.
9. **Экспорт:** «Скопировать отчёт для Excel» копирует итоги и все таблицы.

## 6. Нефункциональные требования

- Интерфейс на русском, валюта — тенге (₸), даты в формате ДД.ММ.ГГГГ.
- Работа в браузере на компьютере и телефоне, светлая и тёмная темы.
- Совместная работа: изменения видны всем пользователям без перезагрузки.
- Если хранилище недоступно, сайт работает в локальном режиме и показывает об этом предупреждение. Если данные не загрузились за 10 секунд, выводится сообщение.
- Пользовательские данные выводятся только как текст (защита от внедрения кода). Ссылки на файлы формируются только из идентификаторов хранилища.
- Ограничения хранилища: до 25 000 записей; файлы до 20 МБ.

## 7. Ограничения текущей версии

1. Уведомления доставляются только на сайте, без почты и мессенджеров.
2. Уведомления формируются при открытии сайта, а не по расписанию на сервере.
3. Формат Word для документов не поддерживается.
4. Печать и прямое скачивание отчёта недоступны; экспорт выполняется через копирование в Excel.
5. Ответственный работник указывается текстом и не связан с учётной записью сотрудника.
6. Изменение суммы требований после создания уведомления У1 не создаёт новое уведомление о корректировке РЗУ.

## 8. Возможные доработки
